# Sol 首次回复与外层耗时拆分

对既有六次无需中途接管的任务重新分析，没有重跑模型或浏览器。对照为原生 Sol/medium 与 R07。数据不支持“Jev 模式让 Sol 做了很长的首轮推理”：六次 Jev 委派的首轮 `reasoning_output_tokens` 都是 **0**。更明显的开销是委派参数输出、会话准备和通信等待。

## 首次输出

| 指标 | 原生 | Sol + Jev |
| --- | ---: | ---: |
| 首 token 时间，中位数 | 7.91 s | 7.46 s |
| 首 token 时间，平均 | 11.45 s | 9.27 s |
| 首轮 input tokens，平均 | 14,159 | 19,070.5 |
| 首轮 output tokens，平均，含 reasoning | 111.83 | 268.00 |
| 首轮 reasoning tokens，平均 | 23.33 | 0.00 |
| 首句进度文字输出完 → 首个工具调用参数完整，平均 | 1.35 s | 6.53 s |
| 用户消息入记录 → 首个完整工具调用，平均 | 8.79 s | 11.75 s |

首 token 使用 Codex 原始 `time_to_first_token_ms`，从 **turn 开始**计时，不是 HTTP 请求发出后的服务端首 token 延迟。原生多选框 seed 11 有模型流断开重试，首 token 为 30.30 秒，拉高了平均值；该样本仍保留，中位数也同时报告。

首个工具调用内容并不相同：原生通常先发现工具，Jev 版直接输出完整委派。Jev 版首轮可见输出更多，包含重复的任务约束、输入值和预算。例如表单 seed 66 的 `task` 参数有 714 字符，重复页面任务、授权边界和停止规则。进度句结束到完整参数之间的 6.53 秒包含生成与可能的流式等待；现有日志无法把它全部归因于解码，也不能单凭输入长度量化 prefill 耗时。

## 完整外层和工具阶段

| 每任务平均 | 原生 | Sol + Jev |
| --- | ---: | ---: |
| 会话准备、进程启动与退出 | 12.91 s | 10.49 s |
| 首轮模型区间：用户消息入记录 → 首个工具调用 | 8.79 s | 11.75 s |
| 中间模型区间：工具返回 → 下个工具调用 | 17.25 s | 0.00 s |
| 最后工具返回 → 最终回答完成 | 5.14 s | 6.34 s |
| 顶层工具调用区间，含 Jev | 2.57 s | 17.10 s |
| 总计 | 46.66 s | 45.67 s |

模型区间包含请求处理、网络、排队、生成和本地调度，不是纯推理时长。启动/退出部分由整个进程耗时减去 turn 区间，再加上 turn 开始到用户消息入记录的区间得到；日志不支持进一步拆出确切的进程启动和退出各自耗时。

此处工具区间用 session 中完整调用到对应返回的时间，涵盖工具发现和包装层，略宽于上一张图的 native MCP 内部计时。因此前图原生工具为 2.10 秒，这里为 2.57 秒；两种分法都与原始总时长闭合，不能混用类别相加。

## 当前选中的表单 seed 66

Jev 版 53.08 秒分为：

- 会话准备、进程启动与退出：**18.01 秒**。其中 turn 开始到用户消息入记录为 **13.49 秒**。
- 首轮模型区间：**15.14 秒**；首轮输出 295 tokens，reasoning 为 0。
- Jev 委派工具：**13.85 秒**，其中 Jev API 为 8.43 秒。
- 工具返回后的最终核验与回答：**6.07 秒**；52 reasoning tokens。

启动区间存在远程 MCP 初始化失败与重试日志。这是与延迟一致的线索，但没有每个初始化子阶段的完整计时，不能把全部 13.49 秒都归因于该次失败。其他保留日志还包括原生多选框 seed 11 的模型流重试，以及 Jev 表单 seed 22 的模型连接重试。表单 seed 11 的后台插件下载警告发生在委派运行中，没有证据说明它阻塞了主任务。

## 可以支持的优化方向

1. 缩短首轮动态输出：通用固定约束尽量由执行器/既有上下文承担，外层只提交任务、必要输入和真正的补充指导。是否能降低延迟需新的真实运行验证。
2. 分别测量已有会话和冷启动流程。当前每题新建 Codex 进程与私有 home，启动成本不代表已运行桌面会话的日常使用成本。不能简单减去启动时间就宣称获得了实测热启动结果。
3. 后续测量应记录 provider 请求起点、首事件和末事件，才能继续区分请求准备、服务端等待、生成和网络。当前证据没有指向需要降低 reasoning effort；六次首轮已报告零 reasoning tokens。
