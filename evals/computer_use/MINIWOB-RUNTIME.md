# 通用执行循环的延迟、输入确认与按需文档：R13–R15

R15 的九次首次尝试全部获得原始满分，费用计量完整。相比复用的原生 Sol/medium：
**费用少 52.7%，总耗时少 38.5%**。这是三个既有任务类型的历史对照，
不是通用桌面可靠性证明，也不是标准 MiniWoB 时限成绩。

| 完整九题 | 历史原生 | R13：连接与观察 | R14：输入选项 | R15：按需文档 |
| --- | ---: | ---: | ---: | ---: |
| 首次满分且只启动一局 | 9/9 | 9/9 | 9/9 | 9/9 |
| Sol + Jev API 等价费用 | $2.216530 | $1.414339 | $1.135005 | $1.048699 |
| 全程秒数，含启动及最终回答 | 608.30 | 429.90 | 421.58 | 374.28 |
| 外层 Sol 请求 | 76 | 43 | 31 | 31 |

原生使用 Codex CLI 0.153.4，本轮机器已升级到 0.155.1。模型仍为 Sol/medium，
题目、随机种子、奖励、300 秒时限和冻结单价不变；旧原生没有重跑。
版本、缓存与网络变化使这些数字只能描述两次运行的差异，不能把全部改善归因于修改。
比较器默认拒绝版本变化；显式允许历史比较时保留版本警告，且不能通过工程验收。
R15 的历史比较数值超过 50% 降本门槛，但版本条件不满足，因此工程验收标记仍为 false。

## 改动及证据

1. **复用 HTTPS 连接。** 旧标准库调用每次强制关闭连接。相同请求的 12 次交错测量，
   原方式六次均值 1.025 秒，复用方式六次均值 0.530 秒（包含首次建连）；后五次均值
   0.443 秒。十二次选择一致。保留系统 HTTP CONNECT 代理与 TLS 验证，不增加推理重试。
   这只证明正常请求开销下降，不把用户携带电脑造成的断网当作待修问题。
2. **减少原生往返。** 应用清单和完整 AX 在一次原生调用中读取；step 下一步复用刚读到的
   操作结果，realtime 每周期重新观察。执行前检查和输入效果验证仍在。
   R13 完整九题中，78 次成功 Jev 请求均值 0.531 秒，69 次复用连接。
3. **输入框出现新选项时重新决策。** 在实际请求期间，输入建议可能晚于输入值出现。
   执行前检查发现新增可选控件，先让 Jev 看见它们，避免直接离开输入框。
   这个规则受 `recheck_target` 控制；其他文字、倒计时变化仍只告警。
   订票 seed 11 的外层请求从 R13 的 14 次降到 R14 的 6 次，seed 66 从 12 次降到 7 次。
   两次都保持首次满分。规则不认识日期、机场或任何 MiniWoB 页面。
4. **修正评测专用授权过滤。** Chrome 会省略链接协议。旧过滤器误把本地 HTTP 链接补成
   HTTPS，将 31 个日期链接全部移出可选动作。现在从相同主机的授权范围恢复协议，
   仍阻止无关路径和明确的错误协议。原生对照不受这个过滤器限制。
   同屏 Jev 回放显示，仅恢复链接仍会请求帮助，因此不能把全部订票开销归因于过滤器。

5. **最终核验无需预先加载原生 API 文档。** `review_completion` 交棒保留完整当前界面、
   历史和现有绑定，仅在外层确实还需原生操作时才加载 18,789 字符的 API/确认策略说明。
   其他求助交棒仍主动提供说明。R14→R15 外层请求数均为 31，费用下降 7.6%，
   耗时下降 11.2%。这两批不是随机交错实验，不能把全部差值归给此一项修改。
   比较器校验原生可执行路径的 AST 哈希一致，改动只在混合执行分支；其他共享代码差异
   仍会拒绝比较，不以无条件放宽哈希校验来获得优势。

R14、R15 六次多选框/表单均没有外层 UI 操作，但表单 seed 11 的外层漏准备 genre，
中途补充了一次输入；只有其余五次可称为没有中途 LLM 介入。三个订票任务均由外层
完成所需推理和最终核验。没有把外层接管隐藏为 Jev 自主成功。

## 真实网站和实时控制仍有哪些不足

使用 R14 候选，另跑四个真实网站任务和一个自建即时小游戏，均完成预定结果。
四个网页任务单独比较，避免用小游戏掩盖网页退步：

| 四个真实网页任务合计 | 历史原生 Sol/medium | 本轮混合版本 |
| --- | ---: | ---: |
| 最终答案检查 | 4/4 | 4/4 |
| API 等价费用 | $1.708339 | $1.573012 |
| 全程耗时 | 440.18 秒 | 494.48 秒 |

这里仅省 **7.9%**，耗时增加 **12.3%**，还没有满足通用场景更快更省的目标。
问题查找任务的外层使用了两次截图，所以这次只能证明 3/4 网页全程不依赖视觉；
不能把 4/4 宣称成全程 AX-only 成功。多站研究中 Jev 新建标签后被评测授权过滤拦住，
随后由外层完成；这个接管也计入费用和时间。报告保留所有接管与失败诊断。
R15 的按需文档变化未重跑这四题，不把 R14 结果冒充 R15 全网站验证。

实时游戏 **12/12，零漏接、零错误**，实际反应时间 1.21–1.52 秒。
配置的 100ms 是最小周期间隔，实际仍受观察、推理、执行延迟约束；不声称达到 100ms
响应，也不声称可以玩马里奥这类高帧率游戏。历史原生实时失败没有重跑，缺少完整计费，
因此不给小游戏配对省钱数字。

这些多步任务证明可复用执行与接管机制正在改善，不能证明任意桌面任务的稳定成功率。
样本少且种子复用，也不足以作统计上的“成功率无显著下降”结论。

另准备了一份 TextEdit 临时 RTF 作本地应用检查。独立进程在应用授权处停下，
尚未执行文档编辑；用户确认前不自动批准。这次不能计作本地应用成功证据，
[阻塞记录](native-editor-followup.json)与网页/游戏分开保留。
